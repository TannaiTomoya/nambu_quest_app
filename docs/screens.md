南部もぐり観光RPG 画面設計

1. 前提

フロントエンドはUnityで実装する

バックエンドはPython / FastAPIで実装する

初期版ではログイン機能を実装しない

ユーザーは匿名セッションIDで識別する

Unity内の画面遷移と、FastAPIのHTTPルートを分けて設計する

プレイ時間は3〜5分とする

API通信に失敗した場合でも、固定の共通報酬と固定の資料館案内を表示する

報酬のうち、称号は決定的に1件選ばれ、豆絞り柄だけが候補内ランダムで選ばれる

3. 各画面の詳細

3.1 タイトル画面

目的

南部もぐりを題材にした3〜5分の観光RPGであることを伝える

QR流入元をセッション情報に保持する

表示内容

タイトル：南部もぐり観光RPG

キャッチコピー

「ゲーム開始」ボタン

必要に応じて「遊び方」ボタン

入力

ゲーム開始

遊び方表示

出力

匿名セッションID

流入元

言語設定

遷移

ゲーム開始 → 操作説明画面

遊び方 → 操作説明画面

3地点すべてには行けない

持ち帰れる記録は最大2件

任意のタイミングで帰還できる

「タイトルへ戻る」

3.8 結果・推薦画面

目的

プレイヤーの選択と資料館の見どころを結び付け、外部行動へ誘導する。

称号と豆絞り柄を表示するが、容姿やガチャ感を主目的にせず、資料館CTAを必ず残す。

表示内容

関心テーマ

推薦見出し

推薦理由

称号（テーマから決定的に選ばれた1件。乱数なし）

豆絞り柄（テーマ対応候補からランダムに選ばれた1件）

種市歴史民俗資料館の短い説明

主CTA

Google Maps補助CTA

承認済みイベント補助カード

主CTA

ゲームに登場した南部もぐりの装備と記録を実物で見る

表示順の方針

報酬（称号・柄）を資料館案内より前面に出しすぎない

抽選結果によって公式詳細やMapsへの導線を隠さない

操作

公式詳細ページを開く

Google Mapsを開く

イベント情報を開く

もう一度遊ぶ（再プレイは強制しない。MVPではコレクション保存なし）

終了する

遷移

公式詳細ページ → FastAPIリダイレクト経由で外部ブラウザ

Google Maps → FastAPIリダイレクト経由で外部ブラウザ

イベント情報 → FastAPIリダイレクト経由で外部ブラウザ

もう一度遊ぶ → タイトル画面（新しい匿名セッションとして扱う）

終了 → 完了画面

5. 実装上の方針

Unityはシーン数を増やしすぎず、パネル切り替えを優先する

推奨構成は TitleScene、GameScene、ResultScene の3シーン

操作説明、地点確認、記録選択、帰還確認、通信中、エラーはパネルで実装する

ゲーム中の空気処理はUnity内で完結させる

FastAPI通信は主にゲーム終了時と外部リンク押下時に限定する

称号はサーバ側で決定的に選び、Unityは表示のみ行う

豆絞り柄のランダム選択もサーバ側で行い、Unityは結果を表示する

ログイン画面は作らない
