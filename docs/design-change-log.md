## 2026-08-01 HTML版を本体へ再構成（Unity・backend・旧docsの削除）

### 変更内容

- `prototype/`（HTML/CSS/JS）を**唯一の本体**とし、Unity版・FastAPI backend・旧設計docsを `main` から削除
  - Unity自由移動版：`archive/t2-free-movement` ブランチに退避済み
  - Unity新ループ移植版：`archive/unity-prep-loop` ブランチに退避済み
  - backend・旧docsはコミット履歴から復元可能
- 単一HTML（`prep-loop-prototype.html`）を `index.html` + `css/app.css` + `js/`（config-loader / analytics / game-state / ui / app）へ分割。ゲーム挙動は不変
- ゲーム数値・地点・景品・表示文言・feature flags を `prototype/config/game-config.json` へ分離。数値（準備12秒・ランク2閾値50%・ランク3閾値85%）は変更なし
- イベント計測クライアントを追加（`game_started` / `game_completed` / `replay_started`、詳細は `docs/tracking-worker.md`）
- 外部リンクを計測Worker `GET /go/:destinationId?sid=` 経由に変更。Worker未達時は直接URLへフォールバック
- 未到達のデッドコード（絵文字紙芝居の装備解除演出）は分割時に削除

### 変更した理由

- 新ループの実装・演出はHTML版が最も進んでおり、スマホ・PCブラウザでそのまま配布できる
- 主KPI（公式情報クリック率）の計測には軽量なWorker+D1で足り、FastAPI+SQLiteの常駐サーバーは過剰
- 会場利用はスマホのモバイル通信を前提とする。オフライン対策として失敗イベントの後送信とリンクのフォールバックを実装済み

### 実物特典導入時のDB移行条件（未解消・暫定）

特典の実発行が決まり、発行数管理・利用済み確認・不正防止が必要になった時点で、発行台帳テーブルと管理者認証を含む構成（D1拡張または専用バックエンド）を再検討する。

## 2026-08-01 計測の冪等性とフォールバッククリック回収（schema_version 2）

ステージング公開前に、再送による重複保存とWorker障害時のクリック欠落を防ぐ変更を入れた。

- 全イベントに生成時1回の `event_id`（UUID）を付与。再送しても同一値。Worker/D1は `UNIQUE` + `INSERT OR IGNORE` で2件目を無視
- 送信をoutbox方式に変更（先にsessionStorageへ保存→成功後に削除）。pagehide・タブ非表示・onlineでも再送
- Worker未達時の直接リンククリックを `official_link_fallback_opened` としてキューへ記録し、復旧後に送信。主KPIの分子に含める
- `environment` をホスト名から自動判別（dev / staging / production）。集計は production で絞る
- destinationId→URLの正は `game-config.json` の `DESTINATIONS` に一元化（Workerもこれを許可リストとして読む想定）

詳細契約は `docs/tracking-worker.md`。

## 2026-07-30 自由探索型から準備タイムアタック型へ

### 変更前（旧設計）

3〜5分の2D探索型RPG。

- プレイヤーが海底を自由に移動する
- 空気100を消費しながら3つの探索地点を訪れる（消費空気 25 / 40 / 60、安全予備15）
- 持ち帰る記録を最大2件選ぶ
- 帰還後、FastAPI が関心テーマを判定して称号と豆絞り柄を返す

### 変更後（新設計）

45〜60秒の短時間ループ。

1. 装備準備タイムアタック（工程を順番にタップ → 残り時間で準備ゲージを連打）
2. 準備ランクの決定（ゲージ到達率で1〜3）
3. 潜水地点の選択（ランクが高いほど遠くへ潜れる）
4. 潜水・宝箱の獲得
5. 仲間が装備を外す演出（豆絞り姿の潜水士が現れる）
6. 結果表示

### 変更した理由

- イベント会場やWeb体験では1分以内の方が回転率と再挑戦性を両立できる
- 自由移動そのものは題材の理解につながりにくく、操作の習熟コストだけが残る
- 「重い装備は一人では着脱できない」という南部もぐりの特徴を、準備工程と装備解除演出で直接伝えられる

### 表現上の判断

- 準備の評価軸は「錘の数」や「速さ」ではなく**準備の完成度**とする。重い装備をたくさん付けるほど優秀、という誤ったメッセージを避けるため
- 装備解除演出の直前に「この装備は、一人では外せないほど重い。仲間と支え合って、ようやく潜水を終える。」を挟み、素顔の公開を文化紹介と接続する
- 「イケメン」等の容姿への言及は、公式説明・ゲーム内テキスト・称号のいずれにも使わない

## 2026-07-31 プロトタイプの演出強化

体験の伝わりやすさを検証するため、プロトタイプの表現を差し替えました。ゲームループ自体は変更していません。

- 導入画面から「検証用プロトタイプ」の注記を削除し、装備なしの2Dキャラクターを表示
- 装備準備の工程完了にあわせて、キャラクターの装備を段階的に変化させる（装備なし → 潜水服 → 胸当て・錘 → ヘルメット・送気）
- 連打フェーズでキャラクターがジャンプ・腕を動かす
- 潜水画面をRPG風HUD（AIR / DEPTH / QUEST・深度ゲージ・探索ログ・潜水士アニメーション）へ改修
- 宝箱を「調べる」ボタン経由の開封に変更（調査中 → 開封 → 景品表示）。宝箱本体のクリックでは開かない
- 装備解除・帰還演出を絵文字から動画（`prototype/assets/nanbu_return_scene.mp4`）へ差し替え。終了で結果画面へ進み、タップでスキップ可能

これによりプロトタイプは単一HTMLではなくなり、動画を含むためローカルサーバー経由での起動が前提になりました。動画は生成AIによる仮素材です。

## 確認待ちの事項

文化的事実に関わるため、想像で確定してはいけない項目です。

| 項目 | 現状 | 確認先 |
|---|---|---|
| 装備工程の正式名称と順番 | 公開記事から暫定作成（潜水服 → 潜水靴 → シコロ → カップ接続 → 腰ベルト・送気 → 前鉛・後鉛）。記事間で錘の取り付け順に揺れがある | 種市歴史民俗資料館 / 種市高校海洋開発科 |
| 豆絞り柄の妥当性 | ヘルメットの下に手ぬぐいで鉢巻をするのは事実。柄が豆絞りかは未確認 | 同上 |
| 装備解除を手伝う人数と役割 | 実習は3人1組（ダイバー1人 + 介添え2人）。演出は介添え2人に合わせる | 同上 |

## 実装上の凍結事項

- 招待券は演出とリンク誘導の検証のみ。実物特典の運営条件（発行主体・原資・定員・利用確認・失効条件）は未確定
- ポイントはゲーム内限定（「もぐりポイント」）。外部価値を持つ地域ポイントや割引券は別フェーズ
- 計測Worker（Cloudflare Pages Functions + D1）は契約のみ確定（`docs/tracking-worker.md`）。デプロイは未実施
